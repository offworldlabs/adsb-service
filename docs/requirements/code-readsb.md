# readsb study — build, SBS input, re-api, aircraft.json

> Machine-extracted by reader agents (2026-08-29). Verify file:line refs before relying on them.

## Facts

- VERSION PIN: vendored readsb is wiedehopf fork v3.16.16, git commit d9a4c62 (committed Mon Aug 17 2026); /root/adsb-service/vendor/readsb/version contains '3.16.16'. Binary reports: 'readsb version: 3.16.16 wiedehopf git: d9a4c62'.
- BUILD/SDR: There is no separate network-only target; all SDR backends are opt-in Makefile vars defaulting to 'no' (Makefile:4-8 RTLSDR?=no, BLADERF?=no, HACKRF?=no, PLUTOSDR?=no, SOAPYSDR?=no). A plain `make` produces a hub binary with zero SDR libs. Verified on this Ubuntu 24.04 host (gcc 13.3.0): clean build in ~16 s; ldd shows only libm, libzstd, libz, libncurses, libtinfo, libc — no librtlsdr/libusb.
- BUILD/LIBS on Ubuntu 24.04 (network-only): build-essential, pkg-config, libncurses-dev (pkg-config --libs ncurses at Makefile:68; can be dropped with DISABLE_INTERACTIVE=yes per Makefile:62-70), zlib1g-dev (Makefile:51), libzstd-dev (Makefile:36). librtlsdr-dev/libusb-1.0-0-dev only needed if RTLSDR=yes. vendor/readsb/required_packages lists the full SDR-enabled set.
- BUILD/OPTIMIZE: base CFLAGS already contain -O2 (Makefile:25); OPTIMIZE is an empty user-override appended to CFLAGS as '-g $(OPTIMIZE)' (Makefile:175) and to the link line (Makefile:196). wiedehopf's own Dockerfile uses OPTIMIZE="-O2 -march=nehalem" on x86_64. LTO=yes optional (Makefile:77-80).
- WITH_UUIDS semantics (plan A0 'verify WITH_UUIDS'): compile-time flag adding -DWITH_UUIDS (Makefile:110-112). Per Makefile:17-19 comment: stores the last RECENT_RECEIVER_IDS (default 32, readsb.h:349-350, overridable via RECENT_RECEIVER_IDS=n) receiver ids per aircraft, slightly increasing memory, and enables the re-api filter '&filter_uuid=<uuid>' (api.c:601-610, first half of UUID used). Distinct flags: TRACKS_UUID (per-trace-position uuid, invalidates persistent state) and PRINT_UUIDS (implies WITH_UUIDS, prints recentReceiverIds into aircraft.json, json_out.c:740-760). Receiver ids come from beast_reduce_plus/net-receiver-id ingest or a 'uuid=<uuid>' element on a --net-connector; a single anonymous ADSBHub sbs_in connector gains nothing from it. wiedehopf's Dockerfile builds a separate 'readsb-with-uuids' binary (make WITH_UUIDS=yes) alongside the plain one — adsb.lol uses that for its ingest/api tier. Both plain and WITH_UUIDS=yes builds verified compiling clean on this host. Recommendation: plain build (WITH_UUIDS=no default) for the Phase A single-upstream hub.
- SBS INPUT WIRING: --net-connector <host>,<port>,sbs_in makes readsb an outbound TCP *client* to the adapter's listen port (help.h:56, net_io.c:1116-1117); alternatively --net-sbs-in-port <port> makes readsb *listen* (help.h:142). Connector supports failover host,port pair, 'silent_fail', and 'uuid=<uuid>' elements (help.h:56). Reconnect delay --net-connector-delay default 15 s (readsb.c:176, help.h:172). Idle kill: an sbs_in connector connection with no data for 2× --net-heartbeat (2×60 s = 120 s default, readsb.c:153) is force-reconnected (net_io.c:751-759; sbs heartbeat_in = '\r\n', net_io.c:112,124-126,1017). The adapter must send data or bare '\r\n' at least every 120 s to hold the connection.
- SBS PARSER — accepted lines (decodeSbsLine, net_io.c:3040-3340): line <2 chars = heartbeat, ignored; length must be ≥20 and <200 else invalid (net_io.c:3046-3049); must split into ≥22 comma fields (net_io.c:3096-3100); field 1 must be exactly 'MSG' — SEL/ID/AIR/STA/CLK lines are counted invalid (net_io.c:3103); field 2 (MSG type) must be exactly 1 char, stored via atoi as sbsMsgType but NEVER branched on — types 1-8 all parsed identically, the type is only echoed on SBS re-output (net_io.c:3106-3109, 3363-3364); field 5 ICAO must be 6 hex chars, optional leading '~' = non-ICAO (net_io.c:3111-3133).
- SBS PARSER — fields consumed (uniformly for every MSG type, each only when non-empty): f11 callsign (A-Z/0-9/space only, else dropped; net_io.c:3166-3182), f12 altitude→baro_alt in FEET (3184-3194), f13 groundspeed→gs (3196-3205), f14 track→heading HEADING_GROUND_TRACK (3207-3216), f15/f16 lat/lon validated to ±90/±180→sbs_pos_valid (3218-3233), f17 vertical rate→baro_rate (3235-3244), f18 squawk decimal (3246-3256), f19 alert flag or mlat receiver-count (3258-3269), f20 emergency flag (3272-3287), f21 SPI (3290-3298), f22 ground flag -1=ground/0=airborne (3301-3308). SBS carries NO geometric altitude → alt_geom is never set from sbs_in (confirms plan §0 req 3). nic=0, rc=RC_UNKNOWN forced (3312-3313). SBS source → SOURCE_SBS, addrtype ADDR_OTHER → aircraft.json "type":"other" (net_io.c:3058-3079; verified live).
- SBS TIMESTAMPING (determines source_timestamp_quantization and seen_pos honesty): readsb parses field 7+8 (date/time MESSAGE GENERATED) with strptime '%Y/%m/%d %H:%M:%S' plus separately-parsed milliseconds, interpreted as UTC via timegm → mm->sysTimestamp in ms (net_io.c:3135-3153). Fields 9/10 (date/time logged) are IGNORED. Sanity clamp: if parsed ts > arrival+1 s or < arrival-20 min, sysTimestamp is silently rewritten to arrival wall clock (net_io.c:3154-3157); unparseable date → arrival wall clock (3158-3161). All aircraft-state 'updated' times and a->seen/a->seen_pos are then set from mm->sysTimestamp (track.c:130,198,2124,1152; track.c:207 d->updated=now), while JSON writers use mstime() wall clock at write time (json_out.c:1011,1104,...). NET RESULT: seen/seen_pos = wall-clock-at-write minus upstream-generated-time, i.e. they HONESTLY include ADSBHub upstream+ingest latency, with ms quantization preserved from the SBS time field. VERIFIED LIVE: feeding MSG,3 lines timestamped 3.0 s in the past yielded "seen_pos":3.414, "seen":3.4 in both aircraft.json and the re-api.
- SBS TIMESTAMP HAZARDS: (a) upstream clock >1 s fast → clamps to arrival time (latency hidden); (b) data >20 min stale → clamps to arrival time, so extremely stale replays would look FRESH — the adapter should enforce its own staleness guard; (c) timestamps are assumed UTC (timegm) — if ADSBHub emitted local time, every line would fall outside the ±window and silently degrade to arrival-time stamping. Verify against live ADSBHub capture in A0 golden fixtures.
- SBS MALFORMED-LINE BEHAVIOR: structurally invalid lines increment stats remote_received_basestation_invalid and are dropped; valid lines increment remote_received_basestation_valid (net_io.c:3319, 3330-3339). decodeSbsLine always returns 0, so the connection is NEVER closed on malformed input (readAscii closes only on handler returning 1, net_io.c:4946-4952). NUL bytes in the stream are replaced with newlines and rate-limited-warned (net_io.c:4922-4936); trailing \r stripped per line (4941-4943). Unparseable numeric subfields in an otherwise valid line are individually skipped (badValue flag, debug-only logging); the rest of the line is still used. UPSTREAM QUIRK: the field-20 (emergency) else-branches test t[21] instead of t[20] (net_io.c:3280-3286) — harmless for us but relevant to fixtures.
- SBS POSITION ACCEPTANCE: sbs_pos_valid positions bypass CPR and go through speed_check + accept_data + incrementReliable(+2) (track.c:2679-2757); with default --json-reliable 1 (help.h:124) a single SBS position is immediately JSON-visible (verified live — first position appears within 1 write interval). RANGE FILTER TRAP: if --lat/--lon are set, SBS positions farther than maxRange from that point are dropped; maxRange default is 450 nmi in code (readsb.c:180, 1852*450) though help.h:69 says 300. With no --lat/--lon, userLocationValid is false and no range filtering occurs → do NOT set --lat/--lon on the aggregate hub (or pass --max-range 0).
- RE-API ENABLE: --net-api-port <port|unix:/path> (single port only, help.h:154) sets Modes.api=1 (readsb.c:2047-2051); unix sockets supported via 'unix:' prefix on any listen spec (net_io.c:789-827), socket chmod 0666 (net_io.c:826). README-api.md recommends unix socket + nginx proxy_pass (location /re-api/ → http://unix:/run/readsb/api.sock:/$is_args$args). API cache is rebuilt every --write-json-every interval (Modes.json_interval, default 1000 ms, floor 100 ms; readsb.c:178,1878-1880; api.c:2068); cached aircraft objects are byte-identical to aircraft.json objects (sprintAircraftObject printMode 0, api.c:924). --api-shutdown-delay <s> serves remaining queries with 503 on new ones during shutdown (help.h:155). '?status' returns 200 for health checks (README-json.md:205-209).
- RE-API QUERY for lat/lon/dist: GET '/?circle=<lat>,<lon>,<radius in nmi>' (api.c:1274-1292: radius nmi ×1852→meters; lat/lon validated ±90/±180). Related: ?closest= (same, one result), ?box=<latS>,<latN>,<lonW>,<lonE>, ?all_with_pos, ?all, ?find_hex/?find_callsign/?find_reg/?find_type/?find_squawk, filters &filter_with_pos,&above/below_alt_baro,&filter_callsign_prefix,&filter_mil/pia/ladd,&filter_uuid (WITH_UUIDS builds). Full list README-json.md:122-203.
- RE-API RESPONSE (api.c:736-780): default envelope {"now": <cache-time s.mmm>, "aircraft":[...], "resultCount": N, "ptime": ms}. With &jv2 (adsbexchange/adsb.lol v2 compatibility): {"ac":[...], "msg":"No error", "now": <cache-time integer ms>, "total": N, "ctime": ms, "ptime": ms} — this is exactly the 'ac array, ms-scale now' envelope plan §0 req 4 needs. circle/closest append per-aircraft "dst" (nmi, 3 dp) and "dir" (true bearing from query point) (api.c:755-759). 'now' is the api cache generation time (buffer->timestamp), so worst-case served staleness adds up to one --write-json-every interval. Verified live: both envelopes exactly as described, SBS aircraft rendered as {"hex","type":"other","flight","alt_baro","gs","track","baro_rate","squawk","lat","lon","nic":0,"rc":0,"seen_pos","alert","spi","mlat":[],"tisb":[],"messages","seen","rssi":-49.5(placeholder; SBS signalLevel=0),"dst","dir"}. No alt_geom, as expected.
- AIRCRAFT.JSON: --write-json <dir> (help.h:104; dir must pre-exist — use systemd RuntimeDirectory=readsb → /run/readsb, the default dir per README-json.md:12), --write-json-every <sec> (default 1, help.h:113). File written to temp + atomic rename (README-json.md:16). Envelope {"now": file-write time s.mmm, "messages": total, "aircraft":[...]}. seen = (write-now − a->seen)/1000 at 0.1 s resolution (json_out.c:820-821); seen_pos = (write-now − pos_reliable_valid.updated)/1000 at 1 ms resolution (json_out.c:730-732) — both are 'seconds before this file's now', where the underlying event time for SBS is the upstream-generated timestamp (see timestamping fact). Aircraft leave the json ~60 s after last message (README-json.md:118). If position older than 60 s but aircraft still present, lat/lon are replaced by a lastPosition{...} object (json_out.c:768-772). --json-separate-alt-ground 0 (default) renders on-ground as "alt_baro":"ground" string, matching the node proxy's expectation (help.h:125). stats.json and stats.prom are also written to the same dir once per minute (stats.c:1103-1116).
- OTHER HUB ARGS: --json-location-accuracy <0-4> controls only the RECEIVER location publication (receiver.json rounding, readsb.c:100-115; default 2=exact; 0 disables and also suppresses per-aircraft r_dst/r_dir, json_out.c:761-763) — it does NOT affect aircraft lat/lon precision (always 6 dp). Irrelevant when --lat/--lon unset. --db-file <aircraft.csv.gz> (tar1090-db 'csv' branch; default none/NULL, readsb.c:154-155,1909-1919; special arg 'tar1090' → /usr/local/share/tar1090/git-db/aircraft.csv.gz) adds r/t/dbFlags (and desc/ownOp/year with --db-file-lt) — needed if the served surface should match adsb.lol's r/t fields. --net-ro-size default 1280 bytes / --net-ro-interval default 0.05 s (readsb.c:186-187, help.h:169-170) — only affect TCP stream outputs (sbs_out/beast/json_out), not the re-api; raise net-ro-size to 8192 if using --net-json-port (help.h:150). --net-bind-address 127.0.0.1 restricts ALL TCP listeners for AI-06/§19 (help.h:134). --net enables networking (--net-only is legacy alias, help.h:132-133). --quiet suppresses stdout decoding output.
- PER-POSITION TCP JSON (spec later-phase hook — EXISTS): --net-json-port <port> or --net-connector proto 'json_out' emits one newline-delimited JSON aircraft object per received position, each with its own now = that message's sysTimestamp (help.h:150, README-json.md:32, jsonPositionOutput net_io.c:3588-3615 using sprintAircraftObject printMode 2, emit gate net_io.c:6332-6333). Throttling: --net-json-port-interval <sec> min interval per aircraft (default 0 = every position, readsb.c:2038); options --net-json-port-include-noposition and --net-json-port-wind-triggered (help.h:152-153). Also exists: VRS json output (--net-vrs-port, 5 s default interval).
- OBSERVABILITY (A3): Prometheus via stats.prom in --write-json dir or --write-prom <file> (help.h:105, stats.c:1103-1116). Key metrics for provider alerts: readsb_net_connector_status{host,port} = seconds since connect, 0 when disconnected (stats.c:855-863) → direct ADSBHubDown/relay-down signal; readsb_messages_basestation_valid / readsb_messages_basestation_invalid (stats.c:826-827) → parse-error-surge alert; readsb_position_count_total/duplicate/garbage and per-addrtype readsb_position_count_other (stats.c:849-853); readsb_aircraft_with_position, readsb_api_request_count, readsb_uptime, readsb_mem_aircraft_*. stats.json exposes 'basestation' accepted counts in remote section (stats.c:564-569).
- SECURITY/BOUNDS: readsb has NO auth and NO rate limiting on --net-api-port — AC-S-01 and per-node rate limits must be enforced by the fronting tier (nginx/adsblol-api/firewall). Input bounds exist: 200-char SBS line cap, buffer NUL handling, bounded net buffers (--net-buffer, 8KB*2^n default n=1).

## Adaptations needed

- Recommended build (verified working end-to-end on this Ubuntu 24.04 host): `apt-get install -y build-essential pkg-config libncurses-dev zlib1g-dev libzstd-dev` then `cd /root/adsb-service/vendor/readsb && make clean && make -j"$(nproc)" OPTIMIZE="-O2"` (RTLSDR=no is the default; use OPTIMIZE="-O2 -march=nehalem" for portable x86-64 binaries per upstream Dockerfile, or -march=native for a pinned host). Do NOT add WITH_UUIDS for Phase A. viewadsb is a copy of the same binary.
- Recommended hub invocation (verified live): `readsb --net --quiet --net-bind-address 127.0.0.1 --net-connector 127.0.0.1,30003,sbs_in --net-api-port unix:/run/readsb/api.sock --write-json /run/readsb --write-json-every 1 --db-file none` with systemd RuntimeDirectory=readsb (the --write-json dir must pre-exist). For direct testing substitute --net-api-port 8042. CRITICAL: do NOT pass --lat/--lon (else the 450 nmi maxRange filter drops far SBS positions); add --db-file <tar1090-db aircraft.csv.gz> only if r/t fields must match adsb.lol output.
- adsblol/api adaptation: point it at readsb's re-api and use the &jv2 envelope — `/?circle=<lat>,<lon>,<dist_nmi>&jv2` returns the exact adsb.lol v2 shape (ac array, ms 'now', 'ground' string alt_baro, dst/dir per aircraft). Served 'now' is the api cache time; worst-case added staleness = one --write-json-every interval (1 s default, can be lowered to 0.1 s).
- seen_pos honesty (plan §0 req 1) comes FOR FREE from readsb because SBS generated timestamps drive all aircraft clocks — verified live (3.0 s injected upstream lag → seen_pos 3.414). BUT the honesty breaks silently in three cases the adapter/A0 fixtures must cover: upstream clock >1 s fast → clamped to arrival; data >20 min stale → clamped to arrival (stale looks fresh — adapter should add its own staleness guard); non-UTC upstream timestamps → clamped to arrival. Verify ADSBHub's actual field-7/8 population, UTC-ness, and ms quantization against a live capture (source_timestamp_quantization_ms is bounded below by readsb at 1 ms; the real value is whatever ADSBHub emits).
- Adapter (A1) protocol obligations derived from readsb's client behavior: readsb dials the adapter (sbs_in connector), reconnects every 15 s (--net-connector-delay) after close, and force-reconnects after 120 s without bytes — so the adapter's close-relay-on-upstream-failure design works natively; when holding a healthy but quiet connection the adapter must emit '\r\n' heartbeats within 120 s. Malformed lines never kill the connection and are counted in readsb_messages_basestation_invalid — use that counter (plus adapter-side metrics) for the parse-error-surge alert; note readsb accepts ONLY 'MSG' lines with ≥22 fields, 6-hex ICAO, length 20-199.
- AuthN/rate limiting (A2, AC-S-01/Q5): readsb's api port is completely unauthenticated and unlimited — terminate it on a unix socket (mode 0666 — protect via /run/readsb directory permissions) or 127.0.0.1 and put ALL auth/mTLS/rate limiting in the fronting tier (nginx/adsblol-api).
- A3 observability: scrape stats.prom from the --write-json dir (written once/min). Alert primitives: readsb_net_connector_status{host="127.0.0.1",port="30003"} == 0 → relay/ADSBHub path down; rate(readsb_messages_basestation_invalid) → parse surge; readsb_aircraft_with_position → CentralStateStalled proxy. Latency measurement (Q7) can use per-aircraft seen_pos from the api since it already embeds upstream age.
- Ambiguities/discrepancies to flag in the design: (1) help.h says --max-range default 300 nmi but code sets 450 (readsb.c:180) — moot if --lat/--lon unset; (2) upstream parser bug: field-20 emergency else-branches read t[21] (net_io.c:3280-3286) — pin fixtures to actual behavior, do not 'fix' expectations; (3) SBS input never yields alt_geom, nic=0/rc=0, rssi placeholder -49.5 — downstream consumers (adsb2dd alt_geom hard-drop) already flagged in plan; (4) '--net-api-port' takes exactly ONE port; (5) aircraft eviction from json/api ~60 s after last message — factor into staleness contract; (6) mm->receiverCountMlat/mlatEPU semantics of fields 19/20 only apply to SOURCE_MLAT (sbs_in_mlat connector), not plain sbs_in.
- Per-position TCP JSON for Phase B/C exists today (--net-json-port / json_out connector, NDJSON, per-message now) — no fork patch needed; design the Phase B tap on it rather than polling aircraft.json.
