## Facts

- (1-route) The v2 geographic query is registered in src/adsb_api/utils/api_v2.py via a factory `_reapi_route` (api_v2.py:18-55) on an APIRouter with prefix '/v2' (api_v2.py:11-15). Two equivalent paths are registered from one call at api_v2.py:124-134: '/v2/point/{lat}/{lon}/{radius}' and '/v2/lat/{lat}/lon/{lon}/dist/{radius}'.
- (1-route) The handler (api_v2.py:40-43) builds readsb re-api params via a lambda (api_v2.py:126): ['circle={lat},{lon},{min(int(radius),250)}'] — radius clamped to 250 (nautical miles), lat/lon passed through as RAW path strings with no conversion — then calls provider.ReAPI.request(params, client_ip=request.client.host) and returns the upstream body verbatim as Response(res, media_type='application/json'). The response is never parsed, validated, or re-serialized by Python; V2Response_Model (models.py:92-98) is attached only for OpenAPI docs (api_v2.py:14).
- (1-protocol) ReAPI client (utils/reapi.py:7-33): validates each param against regex ^[a-zA-Z0-9,=_\.-]+$ (reapi.py:12), appends 'jv2' (reapi.py:24), issues plain HTTP GET to `{REAPI_ENDPOINT}?circle=<lat>,<lon>,<radius>&jv2` (reapi.py:26), aiohttp timeout total=5.0s connect=1.0s (reapi.py:30), new ClientSession per request (reapi.py:31), returns response.text(). REAPI_ENDPOINT comes from env ADSBLOL_REAPI_ENDPOINT, default 'http://reapi-readsb:30152/re-api/' (settings.py:10-12); ReAPI is instantiated in Provider.__init__ (provider.py:139).
- (1-protocol) The upstream is readsb's built-in HTTP API enabled by `--net-api-port=<port>` (readsb help.h:154; single port only; binds Modes.net_bind_address, api.c:2138, so `--net-bind-address 127.0.0.1` gives loopback-only). adsblol/infra runs it on port 30152 on both the hub readsb and a dedicated 'reapi' readsb fed from the hub via beast_reduce (vendor/infra/manifests/default/reapi/default/kustomization.yaml:28,30; hub/default/kustomization.yaml:28). readsb ignores the URL path — only the query string after '?' matters (api.c:1216-1236). 'circle=lat,lon,radius' parsed at api.c:1274-1298; radius is interpreted as NAUTICAL MILES and converted to meters *1852 (api.c:1290); lat/lon bounds checked (api.c:1294-1298); non-numeric values fail parseDoubles -> HTTP 400 (api.c:1762-1767). Exactly one 'main option' (circle/box/all/find_hex/...) is required per request (api.c:1478-1494).
- (1-envelope) jv2 envelope is constructed by readsb, not Python (api.c:737-779): {"ac":[...], "msg":"No error", "now":<int>, "total":<int>, "ctime":<int>, "ptime":<int>}. Units: now and ctime are IDENTICAL values = the API cache buffer generation timestamp in MILLISECONDS since epoch (buffer->timestamp, set from mstime() at api.c:998 and api.c:1031, emitted api.c:771,773); total = match count (api.c:772); ptime = server-side request processing time in ms (api.c:774). The cache is rebuilt every Modes.json_interval, default 1000 ms (readsb.c:178), configurable via --write-json-every with a 100 ms floor (readsb.c:1878-1880). For circle queries each aircraft object additionally carries "dst":<distance nm, %.3f> and "dir":<bearing deg, %.1f> appended by api.c:755-758. Content-Type: application/json, Cache-Control: no-store, Server: readsb/wiedehopf, keep-alive and zstd supported (api.c:1778-1791).
- (1-envelope) Per-aircraft JSON comes from a cache pre-rendered once per interval by apiGenerateJson (api.c:874-935) using sprintAircraftObject printMode 0 (api.c:924, json_out.c:616+). Aircraft included: all with a valid reliable position, plus recently-seen aircraft without position (includeAircraftJson, json_out.c:979-1007; TRACK_EXPIRE=60s track.h:70); circle matching only ever hits aircraft with valid positions (positionless entries get lat/lon INT32_MAX sentinel, api.c:855-864).

- (4-fields) alt_baro: emitted as the JSON string "ground" when airground==AG_GROUND, else integer feet, and omitted when baro alt unreliable (json_out.c:663-667). This is the DEFAULT branch; if readsb ran with --json-separate-ground (Modes.json_separate_ground, readsb.c:1899-1903) it would instead emit numeric alt_baro plus a separate "ground":true/false key and break v2-envelope compatibility — must NOT be enabled on the serving instance. Python model types it Union[int,str] (models.py:33).
- (4-fields) seen = seconds since last message, 0.1 s resolution ('%.1f', json_out.c:820-822). seen_pos = seconds since last reliable position, 1 ms resolution ('%.3f', json_out.c:730-732), present only with a valid position; both floored at 0. CRITICAL SEMANTICS: both ages are computed relative to the CACHE GENERATION time (the same mstime() that becomes the envelope's now/ctime), not the HTTP request time — so client-side reconstruction 'observation_epoch_ms = now - seen_pos*1000' is exact, but time elapsed since the cache build (up to json_interval = 1 s default) is only observable by comparing envelope now against wall clock. seen_pos can reach tens of seconds (position validity persists ~TRACK_EXPIRE 60 s).
- (4-fields) seen/seen_pos measure age since readsb-hub RECEIVED the data on its local clock — ADSBHub upstream/aggregate latency is invisible to readsb's SBS-in path. Plan §0 requirement 1 (seen_pos must include upstream ingest latency) is NOT satisfied by the stack out of the box; it must be measured in A3 (Q7) and, if material, compensated (e.g., adapter-measured latency published as a metric and/or documented in the spec amendment). Also alt_geom (json_out.c:670-671) will be absent for SBS-derived aircraft as the plan predicts.

## Adaptations needed

- Write a new slim FastAPI app (~60 lines) instead of reusing app.py: instantiate ReAPI(REAPI_ENDPOINT) directly (no Provider/Redis/playwright/fastapi-cache), register only the two circle paths (/v2/lat/{lat}/lon/{lon}/dist/{radius} and /v2/point/{lat}/{lon}/{radius}) plus /health. The vendored app.py cannot run without Redis and phones adsb.lol infrastructure even with bg tasks env-disabled (app.py:142-143).
- Declare real, typed path parameters with validation (lat: float ge=-90 le=90; lon: float ge=-180 le=180; radius: float/int ge=0 le=250) — the vendored annotation-injection trick (api_v2.py:46-48) performs NO validation; today non-integer radius causes a 500 and garbage lat/lon leaks through to readsb.
- Fix ReAPI error paths: return a JSON error with proper status instead of the dict-into-Response bug (reapi.py:22 + api_v2.py:43), and map upstream timeout/connection failure (5 s total) to 502/503 with a small JSON body rather than an unhandled 500; reuse one shared aiohttp.ClientSession instead of one per request (reapi.py:31).
- Add a /health endpoint (none exists in the vendored app): proxy readsb's GET /?status (api.c:1750-1759) against the same --net-api-port to report upstream liveness; optionally add a freshness check comparing envelope 'now' (ms) to wall clock (stale if drift >> json_interval).
- Add rate limiting sized for ~1 Hz per node (plan A2) — none exists in the code; adsb.lol does it at their ingress. Options: slowapi/starlette middleware keyed by client IP, or enforce at the fronting proxy along with the AC-S-01 auth boundary (mTLS or network policy — open question Q5).
- Configure readsb-hub with --net-api-port=<port> (e.g. 30152) and --net-bind-address 127.0.0.1 (AI-06 loopback-only; api listener honors net_bind_address per api.c:2138); do NOT set --json-separate-ground (would replace alt_baro:"ground" with a separate ground key and break v2 envelope compatibility); tune --write-json-every (default 1 s, floor 100 ms) as the freshness/CPU tradeoff since it sets both cache staleness and the envelope 'now' cadence. The adsblol separate-reapi-instance pattern is optional on a single host.
- Set REAPI_ENDPOINT via env (ADSBLOL_REAPI_ENDPOINT or a renamed setting) to http://127.0.0.1:<api-port>/re-api/ — keep a path with a '?'-suffixable base exactly as reapi.py builds it (host + '?' + params).
- seen_pos honesty (plan §0 req 1): readsb reports ages relative to its own receive clock; ADSBHub upstream latency is structurally invisible to the serving tier. Design decision needed: measure aggregate latency in A3 (Q7) and either document it in the spec amendment, export it as a metric from the adsbhub-adapter, or (if compensation is required) accept that it cannot be injected into readsb's seen_pos without post-processing the JSON passthrough (which would forfeit the verbatim-envelope simplicity).
- Trim requirements to fastapi+uvicorn+aiohttp (+pytest/pytest-asyncio/aioresponses for tests); keep models.py's V2 models only if OpenAPI docs/fixture validation are wanted. Target Python 3.14 per the vendored pins, or re-compile requirements for the host's Python.
- Record for the A0 license review: adsblol/api LICENSE file is BSD 3-Clause while its pyproject classifier claims MIT (contradiction to resolve upstream or note in SBOM); readsb is GPL-3 (COPYING) and version 3.16.16 is the vendored pin.
- Envelope-compatibility verification (plan A2): capture a live fixture from our readsb --net-api-port with '?circle=...&jv2' and diff against tar1090-node v0.2.0 proxy/server.js:90-129 expectations (ac array, ms 'now', alt_baro 'ground' string, seen_pos seconds). Note circle responses include extra per-aircraft dst/dir keys (api.c:755-758) and jv2 responses include msg/total/ctime/ptime — confirm the node proxy tolerates the extras (it should, it maps known fields).
