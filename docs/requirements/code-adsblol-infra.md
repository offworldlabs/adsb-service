## Adaptations needed

- Replace k8s DNS connectors with loopback: their hub pulls/pushes via service names (planes-readsb, hub-readsb, mlat-mlat-server); single-host hub needs exactly one input: --net-connector=127.0.0.1,<adapter-relay-port>,sbs_in (plan A1 chooses adapter-listens/readsb-dials, which pairs with the adapter's close-relay-on-upstream-failure). Set --net-connector-delay lower than the 15 s default (e.g. 5 s) so post-failure re-attach is prompt.
- Collapse hub+reapi into ONE readsb instance: adsb.lol splits them only for k8s scaling; on one host run a single readsb with --net-api-port for the API and --write-json for tar1090 — removes the beast-reduce hop (30006) entirely.
- Drop mlat/beast/ingest flags from the copied commands: --forward-mlat, --net-connector=...,sbs_in_mlat, --net-garbage=30419, --net-ingest, --net-receiver-id, readsb-uuid binary, and all unused listen ports (30001/30002/30003-out/30004/30005/30006/30047, second 32006 duplicate). SBS input carries no receiver identity, so uuid machinery is dead weight in Phase A.
- Bind private: their isolation is k8s Services/NetworkPolicy; ours must be --net-bind-address=127.0.0.1 (binds every readsb listener incl. 30152) and uvicorn on loopback/private interface behind the Q5 auth boundary. If the API port must cross a host boundary later, prefer --net-api-port unix:/run/readsb/api.sock + nginx (README-api.md) — but adsblol/api's aiohttp needs a TCP URL unless a UnixConnector is added.
- Decide --max-range explicitly: base intent is READSB_MAX_RANGE=99999 (unlimited) but that env is inert on the command-override roles, which silently run the 300 nm default without receiver coordinates — ambiguity in their config; recommend passing --max-range=99999 explicitly (SBS positions arrive pre-decoded; worldwide aggregate).
- adsblol/api single-host env: ADSBLOL_REAPI_ENDPOINT=http://127.0.0.1:30152/re-api/, ADSBLOL_REDIS_HOST=redis://127.0.0.1:6379, ADSBLOL_ENABLED_BG_TASKS= (empty — default tasks resolve k8s hostnames and will error-loop), ADSBLOL_INSECURE only if feeder-uuid endpoints are exercised (note their compose uses the stale name INSECURE=1). A local Redis instance is REQUIRED at startup even for v2-only serving; alternatively trim app.py for Phase A (touches startup + FastAPICache).
- Add what the pattern lacks: per-node rate limiting (no limiter exists in adsblol/api — add nginx limit_req or middleware, plan A2), authN (AC-S-01), and honest seen_pos/now including ADSBHub upstream latency — readsb timestamps on arrival, so upstream age must be measured/injected by the adapter path or documented (plan §0 req 1; nothing in adsb.lol compensates).
- Radius cap divergence: api_v2 clamps dist to 250 nm silently; confirm that is acceptable for the node proxy contract (its queries are small-radius, so yes in practice).
- systemd translation: their probes are tcpSocket:30004 — for us probe TCP 30152 or GET http://127.0.0.1:30152/re-api/?status (200 = healthy); /run/readsb should be a tmpfs (k8s emptyDir equivalent) created via systemd RuntimeDirectory=readsb; Prometheus scraping replaces the port-150 nginx sidecar by reading /run/readsb/metrics (node_exporter textfile or a trivial static file server); jemalloc env (LD_PRELOAD=/usr/local/lib/libjemalloc.so.2, MALLOC_CONF=narenas:1,tcache:false) belongs in the unit file if reproducing their image behavior.
- Freshness tuning: default --write-json-every=1 s bounds both aircraft.json and re-api staleness; planes-test uses 0.5 s — choose 1 s initially and revisit against the node's 5 s budget during A3 latency characterization. --json-trace-interval only matters if globe traces/history are enabled (not needed Phase A).
- Build pin: reproduce katlol/readsb@3ef8808's build style from the vendored wiedehopf Dockerfile: make -j$(nproc) OPTIMIZE="-O2 -march=nehalem" (x86_64), plain binary suffices (WITH_UUIDS variant only needed if filter_uuid/uuid tracking is ever wanted); pin the exact readsb commit per ADR 2 and capture golden JSON fixtures.
- tar1090 on single host: prod planes uses docker-tar1090 env conventions; without Docker, install wiedehopf tar1090 pointed at /run/readsb (aircraft.json from --write-json). --tar1090-use-api + globe-index flags are optional and add nginx re-api mapping complexity — defer.
